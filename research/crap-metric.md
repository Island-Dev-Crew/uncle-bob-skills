## Core mechanism

CRAP scores each method by mixing untested-ness into complexity. Exact formula, verbatim from the authors: **`C.R.A.P.(m) = comp(m)^2 * (1 – cov(m)/100)^3 + comp(m)`**, where `comp(m)` is cyclomatic complexity (1 + unique decisions) and `cov(m)` is automated-test coverage of the method (basis-path coverage in the original; instruction/statement coverage in most implementations) ([Artima pt. 2](https://www.artima.com/weblogs/viewpost.jsp?thread=210575)). Boundary behavior: at 100% coverage CRAP = CC; at 0% coverage CRAP = CC²+CC. Canonical threshold: **>30 is "crappy"**; original project-level allowance: ≤5% of methods over 30; **CRAP Load** = number of tests needed to bring a project under threshold ([crap4j announcement](https://www.artima.com/weblogs/viewpost.jsp?thread=215899)). Corollary: CC>30 can never pass, regardless of coverage ([NDepend blog](https://blog.ndepend.com/crap-metric-thing-tells-risk-code/)).

## Provenance & history

- **Attribution correction:** the creators are **Alberto Savoia & Bob Evans** (Agitar Labs), not "Alberg." ([Artima pt. 2](https://www.artima.com/weblogs/viewpost.jsp?thread=210575), [crap4j post](https://www.artima.com/weblogs/viewpost.jsp?thread=215899))
- July 19, 2007: Savoia unveils the formula in "Pardon My French, But This Code Is C.R.A.P." on Artima ([pt. 1](https://www.artima.com/weblogs/viewpost.jsp?thread=210434), [pt. 2](https://www.artima.com/weblogs/viewpost.jsp?thread=210575)). Oct 2, 2007: **crap4j** ships as an Eclipse 3.2.1+ plugin (JUnit + built-in coverage) ([Artima](https://www.artima.com/weblogs/viewpost.jsp?thread=215899)). Google Testing Blog revisited it in ["This Code is CRAP"](https://testing.googleblog.com/2011/02/this-code-is-crap.html) (2011). The acronym appears both as "Change Risk Anti-Patterns" and "Change Risk Analysis and Predictor" across the authors' own posts.
- **Known criticisms:** the exponents were chosen amid "heated discussions," not empirically calibrated (the authors admit this — [Artima pt. 2](https://www.artima.com/weblogs/viewpost.jsp?thread=210575)); coverage measures execution, not assertion quality, so assertion-free tests game it ([Better Stack](https://betterstack.com/community/guides/ai/crap-metric/)); teams optimize the number without reducing risk ([Qt](https://www.qt.io/software-insights/stop-writing-tests-for-the-wrong-functions-and-releasing-bugs-you-never-saw-coming)); it is per-method-blind to coupling/architecture.
- **Modern tools per language:** Java — [unclebob/crap4java](https://github.com/unclebob/crap4java) (JaCoCo instruction counters, `--changed` incremental mode); Go — [unclebob/crap4go](https://github.com/unclebob/crap4go) (`go test -coverprofile`); Clojure — [unclebob/crap4clj](https://github.com/unclebob/crap4clj) (Cloverage/LCOV); JS/TS — [js-crap-score](https://github.com/ahilke/js-crap-score) (istanbul JSON input); Python — [crap4py](https://pypi.org/project/crap4py/) (self-described port of crap4go/crap4clj; non-zero exit on threshold breach) and Qt [Coco 7.5](https://www.qt.io/quality-assurance/blog/release7.5.0.-coco-now-covers-python-ranks-testing-risk-with-crap-metrics-and-cuts-embedded-setup-overhead-qt-for-mcus); PHP — built into [PHPUnit code coverage](https://docs.phpunit.de/en/12.5/code-coverage.html); Rust — [cargo-crap](https://github.com/minikin/cargo-crap); .NET — NDepend / [crap4dotnet](https://github.com/7Factor/crap4dotnet).

## What holds up in 2026 for agent-directed engineering

The transcript claims check out against public evidence: Martin's GitHub hosts crap4java/crap4go/crap4clj, all actively updated Aug 2026 (verified via GitHub API), and he publicly advocates CC<~4 for functions plus CRAP as the coverage-weighted version ([X post](https://x.com/unclebobmartin/status/2046759028588724443)). His human<4 / agent=6 / experiment-to-8 regime and the specifier→coder→cleaner(CRAP)→hardener(mutation)→QA pipeline are sourced to the interview transcript (primary, local); the "agents have larger accurate short-term memory" rationale is **his claim, UNVERIFIED** as research.

**Threshold regimes.** The math makes low gates elegant: at full coverage CRAP degenerates to CC, so "CRAP<N" ≈ "CC≤N−1 fully tested, OR trivially small and lightly tested" (CC=2 at 0% coverage scores exactly 6 — gate 6 tolerates untested two-path leaf functions; gate 4 does not). Sensible regimes: **hard per-function gate at 6** for agent-written code, **ratchet** (no function's score may rise vs. baseline) for legacy, and a small project budget for exceptions (crap4j's 5%-over pattern). Pair with mutation testing, since coverage-gaming is CRAP's known hole — exactly Martin's "hardener" role.

**Cheap CI.** Complexity is a near-free AST pass; coverage is the dominant cost and you already pay it (JaCoCo/istanbul/coverage.py/`-coverprofile`). So CRAP is ~zero marginal cost: parse the existing coverage artifact, join to per-function CC, gate with non-zero exit (crap4py already does this; crap4java's `--changed` shows the incremental pattern — changed-files-only keeps agent loops fast).

**Per-function vs per-module.** Gate per-function: it's the metric's native grain, deterministic, and gives the agent an exact repair target (split the function or add tests). Use per-module aggregates (CRAP Load, %-over-threshold) only as dashboards/ratchets — aggregates let hot spots hide behind averages.

## Skill seeds

- **crap-gate** — enforce a per-function CRAP threshold as a deterministic agent gate — encodes the formula, the 4/6/8 human-vs-agent regimes, non-zero-exit CI wiring, and the "at 100% coverage CRAP=CC" interpretation.
- **crap-toolchain-map** — pick the right CRAP implementation per language — encodes the verified tool table (crap4java/crap4go/crap4clj/js-crap-score/crap4py/PHPUnit/cargo-crap) and each one's coverage-artifact input.
- **coverage-gaming-audit** — detect assertion-free/gamed coverage behind a passing CRAP score — encodes mutation testing (the "hardener") as the mandatory companion gate.
- **crap-ratchet** — baseline-and-ratchet for legacy codebases — encodes crap4j's 5%-over-30 project budget, CRAP Load as remediation sizing, and no-regression diffs on changed files.
- **agent-threshold-tuning** — run controlled experiments on gate levels (6→8) — encodes Martin's "disciplines are human, values are universal, thresholds are tunable" distinction with evidence capture per level.
- **deterministic-over-steering** — replace prompt rules with tool loops — encodes the lost-in-the-middle rationale for gating agents with exit codes instead of CLAUDE.md prose.
