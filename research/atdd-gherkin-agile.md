## Core mechanism

**Thread A — Gherkin/GWT.** Given-When-Then is a fixed grammar for acceptance criteria: *Given* context, *When* event, *Then* outcome. Its power is dual-audience: readable business language on top, deterministic executable binding underneath (step definitions). It turns "what done means" into a machine-checkable gate rather than prose. Adzic generalizes this as Specification by Example: derive scope from goals, illustrate with concrete examples, automate validation *without changing the specification*, keep it as living documentation ([Manning](https://www.manning.com/books/specification-by-example)). In the transcript's use-case, Uncle Bob's "specifier" agent emits exactly this pair — a Gherkin doc (high-level acceptance test) plus a QA procedure ("run the system through the UI... prove that the system works") — which then gates a coder → cleaner → hardener → QA-agent pipeline (transcript.txt, specifier section).

**Thread B — cost-of-change economics.** Waterfall's premise: change gets exponentially more expensive downstream, so front-load specification. Agile's premise: if you flatten the curve (tests, CI, refactoring), small batches with feedback beat big upfront plans. Bob's 2026 claim: agents drive change cost "as close to zero as I think we're ever going to get it," so his $1-house parable resolves decisively toward "fiddle fiddle fiddle until it looks right" — and spec-driven-development-for-agents is the 1970s temptation replayed (transcript.txt).

## Provenance & history

- **BDD/GWT**: Dan North, "Introducing BDD" (Better Software, March 2006); JBehave started late 2003; the Given/When/Then template co-developed with business analyst Chris Matts as "ubiquitous language" for acceptance criteria ([dannorth.net](https://dannorth.net/blog/introducing-bdd/)).
- **Cucumber**: Aslak Hellesøy, 2008, grew out of RSpec Story Runner; the syntax was later named "Gherkin" to separate language from tool ([InfoQ 10-year Q&A](https://www.infoq.com/news/2018/04/cucumber-bdd-ten-years/), [Wikipedia](https://en.wikipedia.org/wiki/Cucumber_(software))).
- **ATDD/executable specs**: Ward Cunningham's Fit (2002) let customers write tabular executable tests; ATDD spread 2003–2005 via Fit/FitNesse ([Agile Alliance](https://agilealliance.org/glossary/atdd/), [Wikipedia](https://en.wikipedia.org/wiki/Acceptance_test-driven_development)). Adzic's *Specification by Example* (Manning, 2011) codified the practice from team interviews ([gojko.net](https://gojko.net/books/specification-by-example/)).
- **Waterfall**: Royce, "Managing the Development of Large Software Systems," IEEE WESCON 1970 — ironically presented the single-pass model as "risky and invites failure" ([PDF, UMD](https://www.cs.umd.edu/class/spring2003/cmsc838p/Process/waterfall.pdf)).
- **Cost curve**: Boehm's TRW/IBM data (1976 IEEE article; *Software Engineering Economics*, 1981) — late defect fixes up to ~100x ([swreflections](http://swreflections.blogspot.com/2013/09/the-real-cost-of-change-in-software.html)). Beck's *XP Explained* (1st ed., 1999) named the flattened curve "the technical premise of XP" ([Mountain Goat](https://www.mountaingoatsoftware.com/blog/the-cost-of-change-curve-is-outdated)).
- **Iterative history**: Larman & Basili, *IEEE Computer* 36(6):47–56, 2003 — IID traces to the mid-1950s; big-bang waterfall was never the only lineage ([PDF, umd.edu](https://www.cs.umd.edu/~basili/publications/journals/J90.pdf)).
- **2026 echo**: SDD tools (GitHub Spec Kit, AWS Kiro, OpenSpec) arose 2025 against vibe-coding drift; the "reinvented waterfall" critique is live — Scott Logic's Spec Kit review found "a sea of markdown documents" (via [dev.to survey](https://dev.to/mudassirworks/spec-driven-development-what-it-fixes-and-breaks-1co3), [thebcms guide](https://www.thebcms.com/blog/spec-driven-development/)); Kiro doesn't auto-detect implementation/spec divergence ([doit.com](https://www.doit.com/blog/spec-driven-development-with-kiro-ai-code-ownership)).

## What holds up in 2026 for agent-directed engineering

- **Gherkin survives because it's a gate, not a steer.** It's a deterministic pass/fail artifact outside the context window — immune to lost-in-the-middle decay, unlike CLAUDE.md prose (transcript.txt). LLM agents now both write GWT (AutoUAT: generated scenarios judged helpful ~95% of the time — [arXiv 2504.07244](https://arxiv.org/abs/2504.07244)) and execute it (AutoGen multi-agent Gherkin execution — [ACM](https://dl.acm.org/doi/10.1145/3678719.3685692); TestZeus Hercules — [virtuosoqa](https://www.virtuosoqa.com/post/agent-based-ai-reshaping-software-testing)). Computer-use agents make the QA-procedure half executable too, though multi-app OSWorld success is still ~12–20% ([zylos](https://zylos.ai/research/2026-02-08-computer-use-gui-agents/)) — so UI gates need determinized scripts, not raw agent judgment.
- **Big upfront specs decay mid-execution** because the planner can't foresee what execution reveals; Bob: agents "run halfcocked off on some nonsense," plan must be stopped and rewritten (transcript.txt) — Kiro's un-synced spec drift is the tooling confirmation ([doit.com](https://www.doit.com/blog/spec-driven-development-with-kiro-ai-code-ownership)).
- **Ephemeral specs**: with near-$1 change cost, the spec's job is to launch one story through the gauntlet, then die; "the end result... is the specification" — gates + passing code are the durable artifact (transcript.txt).
- **Specification-of-essence**: "don't download those... point your agents at them... build one for YOU" — a working tool as the spec for regenerating a bespoke equivalent (transcript.txt). This is Specification by Example inverted: the example IS the whole spec.

## Skill seeds

- **gherkin-gate** — turn a story into a Gherkin feature + bound step definitions before coding starts — gate: scenarios must fail (red) pre-implementation, pass post, and live outside the prompt as executable files.
- **qa-procedure-author** — emit a human-voiced UI test procedure ("you are a human operating this system") alongside the Gherkin — gate: a computer-use/Playwright agent must convert it into a deterministic script with a binary verdict.
- **ephemeral-spec** — one-story spec that is deleted on merge — gate: merge blocked if the spec file survives; durable truth = tests + architecture checker, not the plan doc.
- **story-batch-sizer** — enforce agile batch size on agent work — gate: reject any plan whose execution horizon exceeds N stories / one gauntlet pass before human feedback (anti-Spec-Kit-waterfall).
- **plan-decay-detector** — mid-execution check comparing plan assumptions to observed repo state — gate: on divergence, halt and force re-plan instead of "halfcocked" continuation.
- **spec-of-essence** — regenerate a reference tool for this repo rather than vendoring it — gate: agent must read the exemplar, produce a local variant, and prove parity via the exemplar's own test suite.
- **change-cost-probe** — periodically measure actual cost-of-change (tokens/time per gauntlet pass) — gate: rising trend flags mess accumulation (Bob's "agents thrash on messy code" signal) before agents start spinning.
